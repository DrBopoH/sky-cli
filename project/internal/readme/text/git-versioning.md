# git-versioning.md — регламент версий и веток

Авторский регламент `MT-git-versioning | vR.sB.C+T.hash`.

## Версия `vR.sB.C+T.hash`

| Часть | Что это |
|---|---|
| `R` | Release. Решает человек, сам не растёт. Растёт только по решению о ломающих изменениях, не при слиянии в `main`. При росте `R` счётчики `B` и `T` сбрасываются. |
| `s` | Состояние: `a` alpha → `b` beta → `s` stable → `m` milestone. Растёт слева направо: массивнее, стабильнее, полезнее. `a` — самая частая. |
| `B` | Build — тема, набор возможностей одного контекста. Выход именованного билда: `B` +1, `C` сбрасывается. |
| `C` | Commit, вес: +1 за каждый именованный коммит. |
| `T` | Total: сумма именованных коммитов мажорной версии, между билдами не сбрасывается. |
| `hash` | Короткий хэш (7 символов) последнего замораживаемого коммита. |

Обратная фиксация инкремента: версия фиксируется ПЕРЕД сбросом разряда (в SemVer — после). Поэтому нуля нет: первая запись `1.1.1`; билд закрыт на `1.1.29`, следующий начинается с `1.2.1`. Хвостовых `.0` нет.

Буква состояния стоит только в ветках выше `dev` (`fix`, `build`, `main`). На `dev` версия без буквы: `v1.1.7+7.abc1234`. Пользователю обычно показывают `R.sB` или `R.sB.C`; `+T.hash` — для разработчиков.

## Два поля боя

**Local** — trunk-based, модифицированный. Анонимная ветка на фичу, атомарные коммиты, шум разрешён (удалил, вернул, переписал — это личная история). Атомарные коммиты и локальная ветка остаются только на машине автора.

**Remote** — защищённая публикация: запрещены авторский push, force-push и local-merge push; всё идёт через PR, workflows и ревью.

```
<модуль>/<дата>-<слово>  →(PR, Squash)→  dev  →(PR, Merge commit)→  build  →(Merge commit)→  main
```

- `dev` принимает только Squash: одна ветка = одна фича = один именованный коммит.
- `build` и `main` принимают только Merge commit, чтобы именованные коммиты не склеивались.
- Обязательные проверки CI на PR. Удаление и force-push запрещены.
- Новая ветка всегда от свежего `origin/dev`, не от вершины прошлой ветки.

## Именованный коммит

Именованный коммит — одна законченная возможность, которую можно назвать одной строкой в журнале изменений. Его сообщение: резюме + версия.

```
Short summary of the feature | v1.3.12+55.abc1234
```

Атомарные коммиты внутри ветки — Conventional Commits: `feat|fix|refactor|perf|test|docs|style|chore: текст`, после типа до 72 символов. Именованный коммит создаётся при Squash в PR, а не руками.

Гранулярность:

- Именованные коммиты частые: один на законченную возможность, под ним 2–6 атомарных.
- Фуллстек-фича режется на атомарные по слоям и смыслу, не одним коммитом на всё.
- Правка к фиче до слияния — ещё один атомарный коммит в той же ветке (или `amend`, пока коммит не на remote).
- Правка к фиче, уже влитой в `dev`, — отдельная ветка и отдельный именованный `fix` (версия +1, своя строка в журнале изменений).

## Ветки

Local: `<модуль>/<дата>-<слово>`. Модуль — набор фич одного контекста (`ui`, `api`, `docs`, `tooling`…). Реестра модулей нет: подойдёт любое латинское слово, кроме служебных имён веток (`dev`, `build`, `fix`, `main`). Модуль есть только в имени ветки, не в именованных коммитах и не в журнале изменений.

Remote: `dev`, `build`, `main`, при необходимости `fix`.

## Сценарии

1. **Обычный цикл.** Фича в локальной ветке → PR → один именованный коммит на `dev` с версией без буквы, `C` +1, `T` +1.
2. **Выпуск билда.** `build` берёт слепок последнего именованного коммита `dev` и получает merge-коммит с буквой: `Build N <состояние> | vR.sB.C+T.hash7`. Без временных веток, без изменения исходников. Первая фича после билда: `B` +1, `C` = 1 (`1.2.1+T`).
3. **Хотфикс после билда.** Баг найден на билде → исправление идёт в `build` через ветку `fix` (копия `dev`, отрезанная от `build`) или прямо в `build`. Версия `R.sB-F.C+T.hash`, пример `1.a1-3.29`: число после «-» и `T` двигаются, `C` нет. Хотфикс не открывает новый билд. После хотфиксов `fix` заливается в `dev` именованным коммитом через PR.
4. **Релиз.** Удачные билды, которые решено публиковать, вливаются в `main` (merge-коммит релиза). `R` при этом растёт только по решению команды.
