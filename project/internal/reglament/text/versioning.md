## Регламент версий

Авторская схема Дока `vR.sB.C+T.hash` без изменений.

- `R` — Release: решает человек, сам не растёт. Первая запись `1.a1.1+1` (нуля нет: версия фиксируется ПЕРЕД сбросом разряда).
- `s` — состояние: `a` alpha → `b` beta → `s` stable → `m` milestone. Буква есть только выше `dev` (fix, build, main); на `dev` версия без буквы: `v1.1.7+7.abc1234`.
- `B` — Build: тема из набора возможностей. У бинаря build — настоящая сборка.
- `C` — вес: +1 за каждый именованный коммит; в новом билде сбрасывается.
- `T` — сумма именованных коммитов мажорной версии; между билдами не сбрасывается.
- `hash` — 7 символов последнего замораживаемого коммита.
- Хотфикс после билда: `1.a1-3.C+T` — двигаются число после «-» и T, C не двигается.

Ветки и коммиты:

- Remote: `dev` → `build` → `main`, всё через PR. `dev` — Squash (одна фича = один именованный коммит), `build` и `main` — Merge commit.
- Именованный коммит: `сводка | vR.B.C+T.hash7`. Заморозка билда — merge-коммит в `build` с буквой: `Build N <состояние> | vR.sB.C+T.hash7`, без временных веток.
- Local: `<модуль>/<дата>-<слово>`, атомарные коммиты с шумом, остаются только локально.
