# OPERATIONS.md — дисциплина операций патча (для разработчика sky)

Для тех, кто добавляет операции в sky-cli. Потребителю нужен только раздел «Операции» в `.sky/readme/readme.md`: он генерируется из реестра `internal/ops` и разойтись с кодом не может.

## Идея

Операция — декларативная инструкция внутри патча: `.sky/operation/<имя>` в zip. Она не файл проекта, не исполняет код и не живёт на диске: sky читает её прямо из архива, поэтому «самоудаляться» нечему, оставшихся файлов нет ни при успехе, ни при ошибке.

## Контракт операции

Операция — одна запись в реестре `internal/ops`:

| Поле | Смысл |
|---|---|
| `Name` | имя файла в `.sky/operation/`, оно же имя операции |
| `Fields` | число и смысл полей записи |
| `Plan(record) → []Effect` | превращает запись в эффекты, ничего не пишет |
| `Doc` | описание для readme; раздел «Операции» собирается из `Doc` всех операций |

## Всё сводится к трём эффектам

`Plan` возвращает только примитивы: `Write(path, content, exec)` и `Delete(path)`; `Mkdir` добавится вместе с первой операцией, которой он нужен. Снимок «до», `manifest.txt`, откат и защита путей работают с эффектами и не знают об операциях. Новая операция не требует правок в `apply`, `rollback` и снимках: это и есть масштабирование.

## Нотация (общая для всех операций)

- UTF-8, LF; одна запись на строку; пустые строки и `#…` игнорируются.
- Поля разделяются табуляцией; пути от корня репозитория, с `/`; пробелы в путях допустимы, табуляция и перевод строки в пути запрещены.
- Одно поле — один смысл; необязательных полей нет (нужен вариант — новая операция).
- Парсер один на все операции: проверяет форму записи и число полей до вызова `Plan`.

## Порядок и безопасность

1. Прочитать все записи, проверить форму.
2. Построить эффекты всех операций и файлов патча.
3. Проверить пути единой функцией `guard` (та же, что для файлов патча); конфликт «путь встречается дважды» — отказ.
4. Снимок «до» по списку затронутых путей.
5. Эффекты операций, затем файлы патча.
6. Ошибка на любом шаге после 4 — откат по снимку.

Правила: неизвестная операция — отказ всему патчу; результат уже достигнут — пропуск с пометкой; результат недостижим (нет источника) — отказ. Операции не запускают ничего внешнего и не принимают шаблоны путей.

## Как добавить операцию

1. Запись в реестре (`Name`, `Fields`, `Plan`, `Doc`).
2. Тесты: форма записи, пропуск при достигнутом результате, отказ при недостижимом, конфликт путей, защита путей, откат.
3. Прогнать `make test`. Раздел «Операции» в `readme.md` обновится сам.

## Операции сейчас и дальше

- `delete` — `путь`: удалить файл.
- Кандидаты на будущее (не реализованы): `move` (`откуда`, `куда`), `mkdir` (`путь`).

## Где что в коде

- `internal/ops` — реестр, нотация (`Parse`), операции.
- `internal/apply` — чтение архива, `GuardPath`, снимок «до», запись, `Restore`.
