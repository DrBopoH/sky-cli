# OPERATIONS.md — дисциплина операций патча (для разработчика sky)

Для тех, кто добавляет операции в sky-cli. Потребителю нужен только раздел «Операции» в `.sky/readme/readme.md`: он генерируется из реестра `internal/ops` и разойтись с кодом не может.

## Идея

Операция — декларативная инструкция внутри патча: `.sky/operation/<имя>` в zip. Она не файл проекта, не исполняет код и не живёт на диске: sky читает её прямо из архива, поэтому «самоудаляться» нечему, оставшихся файлов нет ни при успехе, ни при ошибке.

## Контракт операции

Операция — одна запись в реестре `internal/ops`:

| Поле | Смысл |
|---|---|
| `Name` | имя файла в `.sky/operation/`, оно же имя операции |
| `Fields` | число и смысл полей записи |
| `Plan(record) → Result` | превращает запись в эффекты (и заметки), ничего не пишет |
| `Doc` | описание для readme; раздел «Операции» собирается из `Doc` всех операций |

## Всё сводится к эффектам

`Plan` возвращает только примитивы: `Write(path, content, exec)` и `Delete(path)`; `Mkdir` добавится вместе с первой операцией, которой он нужен. Снимок «до», `manifest.txt`, откат и защита путей работают с эффектами и не знают об операциях. Новая операция не требует правок в `apply`, `rollback` и снимках: это и есть масштабирование.

## Нотация (общая для всех операций)

- UTF-8, LF; одна запись на строку; пустые строки и `#…` игнорируются.
- Поля разделяются табуляцией; пути от корня репозитория, с `/`; пробелы в путях допустимы, табуляция и перевод строки в пути запрещены.
- Одно поле — один смысл; необязательных полей нет (нужен вариант — новая операция).
- Парсер один на все операции: проверяет форму записи и число полей до вызова `Plan`.

## Порядок и безопасность

1. Прочитать все записи, проверить форму.
2. Построить эффекты всех операций и файлов патча.
3. Проверить пути единой функцией `guard` (та же, что для файлов патча); конфликт «путь встречается дважды» — отказ.
4. Снимок «до» по списку затронутых путей.
5. Эффекты операций, затем файлы патча.
6. Если есть операция `commit` — коммит из путей патча (см. ниже).
7. Ошибка на любом шаге после 4, включая коммит, — откат по снимку.

Правила: неизвестная операция — отказ всему патчу; результат уже достигнут — пропуск с пометкой; результат недостижим (нет источника) — отказ. Операции не запускают ничего внешнего и не принимают шаблоны путей.

## Как добавить операцию

1. Запись в реестре (`Name`, `Fields`, `Plan`, `Doc`).
2. Тесты: форма записи, пропуск при достигнутом результате, отказ при недостижимом, конфликт путей, защита путей, откат.
3. Прогнать `cd project && go vet ./... && go test ./...`. Раздел «Операции» в `readme.md` обновится сам.

## Операции сейчас и дальше

- `delete` — `путь`: удалить файл.
- `commit` — `сообщение` и необязательные флаги (`new`): после записи файлов один коммит из путей патча; `new` берёт в коммит и прочие новые файлы дерева, как `sky commit --new`.
- Кандидаты на будущее (не реализованы): `move` (`откуда`, `куда`), `mkdir` (`путь`).

## Один механизм, два интерфейса

Консоль и `.sky/operation/` — две оболочки над одними механизмами; флаги и параметры относятся к интерфейсу, поэтому есть в обеих. Новый флаг вводится сразу в обоих (для `commit` список один: `commit.Flags`, параметры `commit.Options`).

| Механизм | Консоль | Операция патча |
|---|---|---|
| коммит | `sky commit [--new] "тип: текст"` | `commit` + поле `new` |
| запись файла | правка руками, затем `sky commit` | файл в патче |
| удаление файла | `rm`, затем `sky commit` (запись видит удаление) | `delete` |
| откат | `sky rollback [--force \| --keep] [N]` | нет |
| факты, архив, инициализация | `sky look`, `sky up`, `sky init` | нет |

## commit: исключение из «только эффектов»

`commit` не пишет и не удаляет файлы: `Plan` возвращает `Result.Commit` (сообщение), а коммит делает `apply` после записи файлов.

- В коммит идут только пути, которые патч реально изменил (созданные, изменённые, удалённые); `git add -A` не используется, чужое в индексе и дереве не попадает.
- Пути из `.gitignore` пропускаются с пометкой (так не падают патчи с `.claude` и `.sky/clouds/`). Если коммитить нечего, коммита нет, это не ошибка.
- Не больше одной записи `commit` на патч; без неё патч не коммитится.
- Сообщение проверяет общее правило `commit.CheckMessage` (его же использует команда `sky commit`): `feat|fix|refactor|perf|test|docs|style|chore: текст`, после типа не больше 72 символов (в рунах). Язык сообщения sky не проверяет.
- Ошибка коммита (например, git не знает автора) откатывает патч: файлы возвращаются из снимка, индекс очищается, патч остаётся в inbox.

## Ручной коммит как запись (`sky commit`)

Ручная правка и патч дают один и тот же результат (файлы и коммит), поэтому у них одна лента: `sky commit [--new] "тип: текст"` — это патч без собственных файлов. `apply.RunManual` берёт изменённые пути из `git diff HEAD` (с `--new` ещё и новые, кроме игнорируемых), кладёт в `before.zip` версии файлов из HEAD, делает коммит теми же `commitPaths` и дописывает `# commit:`. Снимка в `backups/` нет: файлы коммитом не менялись. Пути, которые патч не принял бы (`GuardPath`), коммитятся, но в запись не попадают (с пометкой). Откат такой записи не отличается от отката патча: файлы возвращаются «до».

## Откат (`sky rollback [--force | --keep] [N]`)

Служебная папка `.sky/stages/` делится на две: `history/` (записи патчей и откатов) и `backups/` (полные снимки проекта перед каждым патчем; `sky up` сюда не пишет). В обеих хранится по 16 последних; самая старая запись history удаляется вместе со своим патчем.

Запись в `history/` — это `before.zip` (прежние версии), `manifest.txt` (`# patch: имя`, строки `статус<TAB>путь`, при коммите `# commit: <полный хэш>`, при снимке `# backup: <имя зипа в backups/>`) и сам патч.

`sky rollback [N]` (soft, N от 1 до 16, по умолчанию 1) — вернуться на N записей назад. Для каждой записи строятся обратные эффекты (созданное — удалить, изменённое и удалённое — вернуть из `before.zip`), от новых к старым; при конфликте путей побеждает самая старая запись. Всё применяется одной новой записью `rollback-…` через тот же `classify`/`saveBefore`/`execute` (`RunEffects`), поэтому откат сам откатывается. Коммиты, созданные откатываемыми патчами, снимаются (`reset --mixed HEAD~k`), только если лежат подряд на вершине ветки; коммиты, которых уже нет в ветке, пропускаются; иначе отказ без изменений.

`sky rollback --force [N]` — вернуть проект к полному снимку «до» N-го с конца патча (`# backup:`). Файлы снимка записываются поверх, файлы, которые знает git и которых в снимке нет, удаляются (кроме больших, >5 МБ). `.sky/sky.conf`, `foryou/` и `readme/` не восстанавливаются. Коммиты не трогаются, команда печатает их хэши. Результат — тоже запись history, её можно откатить обычным `sky rollback`. Если у записи нет снимка (это откат или ручной коммит) или снимок уже удалён, отказ с советом использовать soft.

`sky rollback --keep [N]` — только снять коммиты N последних записей (`reset --mixed`, те же условия «подряд на вершине»), файлы остаются в дереве. Записи сохраняются, у них отметка `# commit:` заменяется на `# был коммит:`, поэтому обычный откат по-прежнему вернёт их файлы «до». Так отменяют или переделывают последний коммит: `rollback --keep`, правка, `sky commit`. Отдельных `undo` и `amend` нет.

## Где что в коде

- `internal/commit` — общие правила коммита: сообщение, флаги и параметры использования; их берут оба интерфейса.
- `internal/gitx` — единственная точка доступа к git: все запуски процесса `git` идут через неё.
- `internal/work` — рабочие процессы ядра: применить патч с полным снимком «до», откат `--force`, проверка чистого дерева; консоль только печатает.
- `internal/ops` — реестр, нотация (`Parse`), операции (`delete.go`, `commit.go`).
- `internal/apply` — чтение архива, `GuardPath`, снимок «до», запись, `Restore`, коммит (`commit.go`), откат (`undo.go`); `record.go` — одна запись history, через неё идут патч, откат и ручной коммит.
