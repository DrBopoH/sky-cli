# PROJECT-GRAPH — реестр модулей sky

Автор: Δρ.ΒοροΗ. · MorangTong creative studio
Назначение: единый реестр систем проекта и связей между ними. Имена модулей отсюда используются в названиях веток `ММДД-ЧЧММ/модуль` (MT-git-reglament, 3.4).

## 1. Правила реестра

1. Модуль — единая система (MT-unify-systems): один пакет `project/internal/<имя>`, одна ответственность.
2. Зависимость — прямой нецелевой импорт. Тестовые импорты не учитываются.
3. Граф ацикличен. Ядро не импортирует `cli`, `ops`, `main`; `cli` и `ops` друг друга не вызывают.
4. Новый модуль, новая или снятая зависимость меняют этот файл в том же именованном коммите.

## 2. Модули

| Модуль | Ответственность | Зависит от |
|---|---|---|
| notation | разбор нотации диапазонов и путей | — |
| guard | допуск путей, чувствительные файлы | — |
| history | журнал патчей, коммитов, бэкапов | — |
| gitx | единственная точка доступа к git | — |
| commit | сообщения и параметры коммитов | — |
| conf | конфигурация | — |
| version | версии | — |
| named | версия именованного коммита: разбор и запись сообщения | — |
| graph | чтение реестра модулей, цепочки от зерна | — |
| readme | статические тексты (встроенные) | — |
| repo | состояние репозитория | gitx |
| pack | упаковка архивов | gitx, guard |
| look | просмотр состояния и журнала | conf, gitx, history |
| land | перенос фичи в граф веток по регламенту, версия по истории dev | gitx, graph, named |
| apply | план эффектов, проверка, запуск, откат | commit, gitx, guard, history, notation |
| ops | патч-операции, адаптер плана | apply, commit, guard, notation |
| work | применение патча, откат | apply, gitx, guard, history, pack, repo |
| cli | команды и оркестрация | apply, commit, conf, history, land, look, pack, readme, repo, version, work |
| main | зерно: сборка и запуск | cli, ops, readme |

## 3. Уровни

| Уровень | Модули |
|---|---|
| 0 (листья) | notation, guard, history, gitx, commit, conf, version, readme, named, graph |
| 1 | repo, pack, look, apply, land |
| 2 | ops, work |
| 3 | cli |
| 4 | main (зерно) |

Уровень модуля — длина самой длинной цепочки зависимостей вниз. Ветка модуля вкладывается в ветку зависимого модуля на уровень выше (цепочка `dev → /work → /pack → /gitx`).

## 4. Зерно и сироты

- Зерно: `main` (точка входа), связывает `cli`, `ops`, `readme`.
- Сирот нет: каждый модуль достижим из зерна.

## 5. Зафиксированные отклонения

Оркестрация `init`/`up` живёт в `cli`: второго потребителя нет, выделение в отдельную систему не оправдано. Пересмотреть при появлении второго потребителя.
