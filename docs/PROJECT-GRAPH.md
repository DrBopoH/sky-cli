# PROJECT-GRAPH — реестр модулей sky

Автор: Δρ.ΒοροΗ. · MorangTong creative studio
Назначение: единый реестр систем проекта и связей между ними. Имена модулей отсюда используются в названиях веток `модуль/ММДД-ЧЧММ` (MT-git-reglament, 3.4).

## 1. Правила реестра

1. Модуль — единая система (MT-unify-systems): один пакет `project/internal/<имя>`, одна ответственность.
2. Зависимость — прямой нецелевой импорт. Тестовые импорты не учитываются.
3. Граф ацикличен. Ядро не импортирует `cli`, `ops`, `main`; `cli` и `ops` друг друга не вызывают.
4. Новый модуль, новая или снятая зависимость меняют этот файл в том же именованном коммите.

## 3. Уровни

| Уровень | Модули |
|---|---|
| 0 (листья) | notation, guard, history, gitx, ghx, commit, conf, version, readme, named, graph |
| 1 | repo, pack, look, apply, vhist, modules, pr, protect |
| 2 | ops, work, land, build, fix, feature, publish, sync |
| 3 | merge |
| 4 | cli |
| 5 | main (зерно) |

Уровень модуля — длина самой длинной цепочки зависимостей вниз. Ветка модуля вкладывается в ветку зависимого модуля на уровень выше (цепочка `dev → /work → /pack → /gitx`).

## 4. Зерно и сироты

- Зерно: `main` (точка входа), связывает `cli`, `ops`, `readme`.
- Сирот нет: каждый модуль достижим из зерна.

## 5. Зафиксированные отклонения

Оркестрация `init`/`up` живёт в `cli`: второго потребителя нет, выделение в отдельную систему не оправдано. Пересмотреть при появлении второго потребителя.
