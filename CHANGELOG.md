# Changelog

Версии: `R.sB.C+T.hash`. В `dev` буквы состояния нет (`v1.1.C+T`), она появляется в `build`: `v1.a1.C+T`. Правила: MT-git-reglament, смысл нумерации: MT-fix-before-reset. Каждая запись — один именованный коммит (одна функция). Файл ведётся вручную.

## Build 12 — в работе

- **v1.12.1** — `.github/workflows/check.yml`: на каждый PR в `main`, `dev` и `build/**` GitHub гоняет `gofmt`, `go vet`, `go test ./...` и `go build ./...` в `project/` (для тестов задаётся имя и почта git); файл ведёт агент, sky его не генерирует; обязательной проверкой её делает следующий шаг в `sky protect`

## Build 10 — `v1.a10.9+68`

- **v1.10.9** — `sky apply --land "резюме" --module M | --seed`: патч сразу в слой, без ветки `wip` (патч — готовая фича без шума): самый старый патч из inbox применяется на detached HEAD от `dev`, `land` вливает этот коммит (новый параметр `land.Options.Source`: источник — коммит, а не ветка), общие ветки пушатся, остальные патчи ждут; при сбое слияния заводится `wip` для разбора (`project/internal/cli/apply.go`, `project/internal/land`)
- **v1.10.5** — Слой `cli` и `repo` одной пачкой: `sky init` в свежем клоне берёт `dev` из `origin/dev`, а не отводит от `main` (раньше истории расходились, и `sky merge` с `sky sync` отказывали); `sky publish` пушит `main` в `origin` без force, как `land`, `fix` и `build`, `--local` отключает (`project/internal/repo`, `project/internal/cli`)

## Build 9 — `v1.a9.2+59`

- **v1.9.2** — `sky land` и `sky fix` сами пушат общие ветки (модуль, `dev`, сборка), изменившиеся после операции, если есть `origin` (без force; сбой push операцию не отменяет, sky называет, чем повторить); `--local` отключает; после land не нужны отдельные шаги отправки; `sync.Tips` и `sync.Publish` — одна точка отправки общих веток (`project/internal/sync`, `project/internal/cli`)

## Build 8 — `v1.a8.2+57`

- **v1.8.2** — `sky build` пушит ветку сборки в `origin` (без force; без `origin` или при сбое push сборка остаётся, sky подсказывает команду): ветки сборок общие, исправления идут в них PR (`project/internal/build`)
