# Changelog

Версии: `R.sB.C+T.hash`. В `dev` буквы состояния нет (`v1.1.C+T`), она появляется в `build`: `v1.a1.C+T`. Правила: MT-git-reglament, смысл нумерации: MT-fix-before-reset. Каждая запись — один именованный коммит (одна функция). Файл ведётся вручную.

## Build 4 — в работе (`v1.a4`)

- **v1.4.4** — План удалённой части (`sky pr`, `sky sync`, `sky merge`, `.github` из конфига): кто ставит версию, что пушит автор (`docs/ARCHITECTURE.md`)
- **v1.4.3** — Набор команд по регламенту веток закрыт: `sky modules` (реестр модулей по уровням, зависимости, цепочки от зерна, ветки модулей и их состояние; граф отвергает циклы), `sky publish` (голова сборки одним коммитом в `main` через `commit-tree`, версия головы сборки, повторные публикации без конфликтов) и `dev` при `sky init` в репозитории с историей (от вершины `main`/`master`); новые пакеты `modules`, `publish`, общие `vhist.Pick` (выбор сборки для `fix` и `publish`), `gitx.BranchConfig`, `modules.ParseBranch` (`project/internal/modules`, `project/internal/publish`)
- **v1.4.2** — Команда `sky feature`: локальная ветка `wip/ММДД-ЧЧММ/имя`, цель (модуль с цепочкой, зерно, исправление сборки) запоминается в git config, `sky land` и `sky fix` берут её без флагов; подсказка модулей из реестра; `graph.Load`/`Resolve` общие с `land`; в регламенте закреплено имя локальной ветки (`project/internal/feature`)
- **v1.4.1** — Команда `sky fix`: исправление сборки одним squash-коммитом на ветку сборки (`vR.sB-F.C+T.hash`, по умолчанию в последнюю сборку, `--build`, `--dry`); `T` растёт от `dev` и всех исправлений, следующая версия `dev` его продолжает; новый пакет `fix`, `gitx.SquashInto` общий с `land`, `vhist` знает исправления (`docs/CLI.md`, `project/internal/fix`)
